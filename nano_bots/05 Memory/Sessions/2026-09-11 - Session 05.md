# 2026-09-11 — Session 05: Assign & Check In wizard progress persistence

## Work completed

The Front Desk "Assign & Check In" wizard (4 steps: Identity → Financial → Room →
Check in) restarted at step 1 every time the modal was closed and reopened, forcing
the front desk to redo the whole flow. Cause: the dialog unmounts on close and its
open effect hard-reset `setStep(0)` on remount.

Fix — wizard progress is lifted to the parent, in-memory and session-scoped (per
reservation, no localStorage):

- `components/manager/front-desk-arrival-dialog.tsx`
  - New exported `ArrivalProgress` type + optional `resume` / `onProgress` props.
  - `resumeRef = useRef(resume)` — mount-time capture only (the parent keys the
    dialog per open, so later prop changes are ignored by design).
  - Open effect initializes step / selected / exceptionMode from the resume; everything
    else still resets and refetches.
  - New onProgress effect reports `{step, selected, exceptionMode}` upward; the
    transient mount-time report converges to the true state in-mount.
  - `loadRooms` now returns the mapped rooms array.
  - Room-step effect is resume-aware: on the first load after (re)open the saved room
    selection is re-validated against live inventory — restored when still eligible,
    or the wizard clamps back to the Room step when it isn't. The resume survives the
    detail fetch (consumed only when the load actually runs). Server gates unchanged:
    the RPC still rejects stale rooms at check-in.
- `components/manager/manager-dashboard-client.tsx`
  - `arrivalResume: Record<string, ArrivalProgress>` — one slot per reservation key
    (`id:exceptionType`), so peeking at another guest mid-arrival never clobbers a
    saved flow; cleared on successful check-in; different reservations start fresh
    (walk-in flow included).
  - `handleArrivalProgress` useCallback with a shallow-equality bail-out (no re-render
    loop, no redundant dashboard renders).
- `components/manager/front-desk-arrival-dialog.test.tsx`
  - 4 new tests (resume at Room step with selection restored; resume at Review step +
    onProgress report; clamp to Room step when the saved room is no longer eligible;
    resume of an active exception mode). 15/15 in the file.

Unchanged: `front_desk_check_in` RPC and all server gates, step validation, exception
request flow, eligible-rooms / approvals APIs, walk-in flow, Modal, all CSS.
