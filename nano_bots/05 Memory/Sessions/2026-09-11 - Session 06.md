# 2026-09-11 - Session 06 - Staff Notification Badges + Toasts

## Work completed

The operational staff dashboard (`ManagerDashboardClient`) now has three complementary
notification surfaces with distinct meanings:

1. **Sidebar module badges** — pending actionable workload per module, role-gated to what the
   signed-in staff member can act on:
   - Guest Requests: front desk/manager → distinct pending submission batches; housekeeping/
     maintenance → approved requests routed to their department (open/in-progress)
   - Transportation: `REQUESTED` rides (front desk/manager)
   - Approvals & Escalations: pending approvals (manager only)
   - Housekeeping: open tasks (pre-existing meaning, unchanged)
   - Maintenance: open work orders
   - Deposit Verification: `pending_verification` payments (**accounting only**)
   - Refunds: pending + failed (**accounting only**)
   - Compact amber pill, `99+` cap, absent at 0; collapsed category header sums its modules.
   - Deliberately NO badges on Reservations/Rooms/Guests/Inventory/Billing/Transactions/Folios/
     Cash & Shifts/Reconciliation/Documents/Reports (no true actionable-pending semantics).
2. **Header bell** — kept as the existing live derived alert list (popover unchanged); the button
   now shows the live alert count pill.
3. **Transient toasts** — new `components/ui/toast-stack.tsx`: bottom-right stack, max 3 visible
   with overflow queued, 6 s info / 8 s warning auto-dismiss, pause on hover/focus, × removes only
   the popup, optional "View" action navigates to the alert's module, `aria-live="polite"`,
   reduced-motion covered by the global kill switch. `notify()` action feedback uses the same
   stack (success tone).

## Key decisions

- **Bell stays derived/live — no persistent read/unread notifications.** No `staff_notifications`
  table, no schema change, no migration. Alerts resolve with the underlying work. This keeps
  badge (workload) vs bell (alerts) unambiguous and avoids a second notification system
  duplicating `getDashboard`'s derivations. User confirmed this direction.
- **No Supabase Realtime.** The browser never talks to Supabase (service-role-only, zero public
  policies); realtime would require anon-key + RLS policies, violating the security model.
  Refresh stays on the existing 30 s poll cadence.
- **Badge counts are domain queries computed server-side** in `getDashboard` (new metrics:
  `pendingRequestBatches`, `departmentRequests`, `transportationRequested`, `pendingVerifications`,
  `pendingRefundCount`) — never notification counts, never total record counts. Front Desk never
  gains a Deposit Verification badge (read-only queue view; verification authority stays
  Accounting-only, both layers).
- **Toast diffing seeds silently on first poll** — a page refresh never replays historical alerts
  as toasts; only alerts appearing after initialization toast. Id-based dedup covers re-delivered
  polls.
- **Alert polling fixed for non-Overview sections**: new `refreshAlerts` 30 s interval fetches
  `/api/manager_dashboard` when the active section isn't Overview/Reports — previously the badge
  and bell froze stale outside those sections.
