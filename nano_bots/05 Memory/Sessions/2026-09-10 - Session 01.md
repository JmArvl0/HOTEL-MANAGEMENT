# 2026-09-10 - Session 01 — Intent-aware room discovery (landing → /booking/search)

Landing CTAs now carry distinct intents into one search page, per user spec. No booking
business logic touched (holds, 15-min expiry, pricing, inventory, deposits, payment,
confirmation, auth all unchanged).

## What was built

- `parseSearchIntent` + `RoomTypeSummary` + `getRoomCatalog` in `lib/booking.ts`:
  mode derives from the URL (valid `checkIn`+`checkOut` → availability; otherwise browse,
  with the zod message surfaced as a notice). `roomType` adds focus in either mode.
- `/booking/search` and `/account/find-room`: mode-aware hero/results/sidebar, focus
  sorting + `RoomFocus` scroll (reduced-motion aware), per-mode notices for unknown or
  sold-out focused types, aggregate chip fixed to real physical inventory
  ("M room types · N rooms available"), guest redirect now forwards `roomType`.
- `RoomResults`/`RoomDetails` accept the summary union (`"availableUnits" in room`):
  browse cards show "Check dates" badge + "From ₱X / night" + "Choose dates" →
  `#book-form` — never fabricated availability, never fabricated dates for
  `/booking/details`. Focused card gets `is-focused` + "Selected from homepage" text chip.
- Landing: `BookingIntentProvider` client context; hero form starts with empty dates
  (`emptyDates`) and reports intent; featured cards link `?roomType` alone until dates
  are picked, then carry `checkIn/checkOut/guests`.
- Tests: `parseSearchIntent` unit tests, `emptyDates`/`onIntentChange` form test,
  room-catalog content assertions. SYSTEM.md §7.2 documented.

## Verification

All four gates green (tsc clean, lint 0 errors, full suite green, build clean).
Browser-verified TEST A–D + regressions (invalid roomType/dates/guests → graceful browse
with notice, 390px no overflow, back/forward state via URL, refresh = fresh load).

## Gotcha hit

The dev server served a stale compile of the search page mid-verification (a11y snapshot
showed copy that no longer existed on disk). A background `npm run build` flushed `.next`
and forced recompile from disk. Lesson: when snapshot and `evaluate_script` disagree,
trust the DOM query and force a recompile before diagnosing "missing" UI.
