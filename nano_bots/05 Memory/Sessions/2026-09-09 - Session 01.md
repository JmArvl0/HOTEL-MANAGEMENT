# 2026-09-09 — Session 01: Booking Review page layout polish

**Scope:** Customer booking flow → Review step (`/booking/review/[token]`). Presentation-only
refinement via the `/impeccable` polish mode (Operate). **No booking, pricing, hold, or payment
logic changed** — guards, hold math, recovery URLs, and the payment link are byte-identical.

## What changed

- `app/(booking)/booking/review/[token]/page.tsx` — one cohesive `.review-card` with internal
  sections (Guest details / Stay preparations / Transportation request / Reservation deposit /
  action footer). Label-over-value detail grid replaces the spreadsheet-style `dl` rows;
  preparations render as read-only chips (`.review-chips`), special requests as a quoted note;
  deposit becomes two bordered financial tiles (`Deposit due now`, `Remaining balance`) with the
  policy sub-labels; the **Continue to reservation deposit** CTA moved **inside** the card footer
  next to the hold countdown. Subtle "Edit guest details" link in the Guest details header
  reusing the exact breadcrumb `/booking/details` URL (no new navigation behavior).
- `components/booking/hold-countdown.tsx` — expiry math and redirect untouched. A11y fix:
  visible ticking label is now `aria-hidden`; a single `sr-only aria-live="polite"` span
  announces only on minute/urgency transitions (≤5 min) instead of every second. New
  `data-urgent` attribute below 5 minutes drives a stronger amber treatment (not red).
- `app/guest-booking.css` — replaced the old dark-brown `.hold-countdown` bar with a warm amber
  callout (`--cp-*` aware, works in dark + light theme). New scoped `.review-stage` block:
  tighter stage grid (`gap:36px`, max-width 1240px), section rhythm, chips, finance tiles,
  `.review-actions` footer; ≤900px stacks with the stay summary first (`order:-1`, sticky off);
  ≤680px full-width CTA. All rules scoped to `.review-stage` so the shared details/payment
  `.booking-stage` layouts are untouched.
