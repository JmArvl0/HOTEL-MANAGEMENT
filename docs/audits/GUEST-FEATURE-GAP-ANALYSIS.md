## Feature and scope decisions for implementation

| Classification | Change | Why, placement and dependency |
| --- | --- | --- |
| Essential | Approved payment channel or complete assisted booking | Guests must be able to secure a stay. Place a clear channel decision on search and exact room actions. Depends on the signed-off Hotel/Finance payment and reconciliation contract. See GUEST-001–002. |
| Essential | Privacy notice | Guests provide name, email, phone and optional transportation details. Surface a dedicated, reviewed notice before signup and from help. Hotel owns publication, approved handling and the privacy contact. See GUEST-003. |
| Essential | Accurate cancellation and refund state | Help a guest who has already paid understand what happens next. Use the existing confirmation and payments screens with recorded cancellation and refund facts. Finance owns payout and acknowledgment. See GUEST-013 and GUEST-016. |
| Highly recommended | Shared quote with dated nightly prices and add-ons | The guest compares totals and inclusions during selection and again before payment. Use one display model derived from the existing authoritative rate/hold functions. See GUEST-004–005. |
| Highly recommended | Compact phone arrival pass | The guest generally presents their phone at the front desk. Reflow the existing pass, preserve access controls and validate the physical reader. See GUEST-014. |
| Useful enhancement | Pre-hold recovery and assisted amendment handoff | Let guests recover from an interruption without storing broad personal data. Put restricted stay changes directly in the help flow with the reservation reference. See GUEST-008 and GUEST-017. |
| Useful enhancement | Search results with zero actual sellable rooms | Lead with a clear empty state and an edit-dates or contact action. Preserve the existing nightly availability service and verify across fully occupied, maintenance and party-size fixtures. See GUEST-018. |
| Optional | Side-by-side room comparison | The existing capacity, bed, amenities and price facts can first be made consistent. A separate comparison tool is valuable only if the real property catalogue grows and users repeatedly need it. |
| Redundant | Duplicate create-account action within booking sign-in | The tab already opens the account step. Retain one clear entry adjacent to sign-in and a compact selected stay summary. See GUEST-011. |
| Unnecessary | Guest administrative statistics, unsolicited marketing ratings or feature-heavy account panels | The stay, next action and balance already answer the high-value questions. Reviews, facts and ratings should come from approved content if used. |
| Out of scope for the Hotel app | Fleet dispatch, external revenue journal and provider payout execution | The Hotel records requests and needs status/fare/acknowledgment. Fleet and Finance own their respective operational actions. Retain the integration boundary. |
